# Gotchas

## 常见错误

- 用 MVVM 名义把网络、缓存、导航、埋点都塞进 ViewModel。
- 页面直接请求网络，导致鉴权、错误码、重试、日志分散。
- DTO 直接传 UI，导致后端字段变化扩散到页面。
- 登录态、用户信息、会员状态被多个页面各自缓存。
- 导航、Toast、Dialog 放进可重放状态，页面重建后重复触发。
- Coordinator 写业务规则，变成第二个业务层。
- `Task {}` 没有生命周期，页面退出后仍写状态。
- 非主线程更新 UI 状态。
- Cell 复用没有重置旧图片、加载状态、订阅或任务。
- 键盘避让写固定高度。
- 用 `UIScreen.main.bounds` 作为主要布局依据。
- 只看默认字号、默认语言、单一 iPhone 设备。
- token 存 UserDefaults。
- 日志打印 token、手机号、邮箱等敏感信息。
- 初始化方法里做网络、数据库、重 IO。
- 只写 UI Test，不写 ViewModel、UseCase、Mapper、Repository 单测。

## 常见借口和拒绝方式

- “先这样，后面再抽”：如果已经是第三处重复，先抽或明确不抽的短期理由。
- “页面里写最快”：如果涉及网络、存储、鉴权、共享状态，必须下沉。
- “只有这个页面用”：如果是主题、弹窗、Toast、Loading、Error，不应页面私有化。
- “这个设备没问题”：必须检查小屏、大屏、iPad、字体放大和键盘。
- “只是 UI 改动不用测”：至少验证视觉状态和关键交互。
- “加个延时就好了”：延时通常是竞态症状，不是根因。
- “先强刷一下”：强刷通常掩盖状态源错误。

## 快速定位提示

- 重复弹窗：检查一次性事件是否在长期 state。
- 数据不同步：检查共享状态是否有多个来源。
- 页面退出后崩溃：检查 async callback、Task、observer、subscription。
- 字体放大错乱：检查固定高度和单行约束。
- iPad 错位：检查是否依赖设备型号或屏幕宽度。
- 弱网错乱：检查请求顺序和 stale result。
- 登录失效不一致：检查是否统一走 Session/AuthInterceptor。
