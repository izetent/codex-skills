# 测试、Review、交付

## 目录

- 测试分层
- 验证策略
- 代码审查
- 提交前检查
- 最终说明

## 测试分层

按风险选择：

```text
Unit Test
  ViewModel
  UseCase
  Mapper
  Repository
  Cache Policy

Snapshot Test
  关键页面
  Loading/Empty/Error
  Dark Mode
  Dynamic Type
  长文案
  iPhone/iPad

Integration Test
  登录
  会话恢复
  缓存加网络
  提交/支付/发布

UI Test
  核心端到端路径
  冒烟测试
```

必须补测试或明确说明原因：

- 鉴权。
- 支付。
- 存储迁移。
- Repository 缓存策略。
- 共享状态。
- 导航 contract。
- 复杂 ViewModel。
- 关键视觉页面。

## 验证策略

最少验证：

- 编译通过。
- 原始路径通过。
- 邻近回归路径通过。

UI 改动额外验证：

- 小屏。
- 大屏。
- iPad。
- 暗黑模式。
- 字体放大。
- 键盘。
- 长文案。

数据改动额外验证：

- 成功。
- 失败。
- 空数据。
- 缓存命中。
- 缓存过期。
- 登录失效。

## 代码审查

优先看：

- 改动是否在正确层。
- 依赖方向是否正确。
- 页面是否过厚。
- 状态是否单一来源。
- 一次性事件是否正确处理。
- 网络、缓存、存储是否统一入口。
- UI 是否复用设计系统。
- 是否适配小屏、大屏、iPad、暗黑、字体放大。
- 是否有内存泄漏、竞态、生命周期风险。
- 测试是否覆盖风险。

Review 输出优先级：

1. 崩溃、数据错误、安全问题。
2. 生命周期、并发、状态重复、重复事件。
3. 架构边界和依赖方向。
4. UI 适配、设计系统、可访问性。
5. 测试缺口和可维护性。

## 提交前检查

- 文件是否放在正确目录。
- 是否有无关重构。
- 是否有临时日志。
- 是否有硬编码密钥、URL、文案。
- 是否有强制解包风险。
- 是否有主线程重 IO。
- 是否破坏现有设计 token。
- 是否补齐 loading/empty/error。
- 是否验证原路径。

## 最终说明

实现类任务最终说明：

- 现象或目标。
- 当前 iOS 基线。
- 差异落在哪一层。
- 根因或架构判断。
- 最小修改范围。
- 改动文件。
- 验证方式。
- 未覆盖风险。

如果无法验证，必须说明原因和建议验证命令或路径。
