# 排查流程

修改缺陷代码前使用本文件。

## 最小缺陷定义

记录：

- 现象
- 触发条件
- 影响区域
- 复现路径
- 是否稳定复现
- 关联旧业务路径或相似功能

## 证据优先顺序

1. 现有日志
2. 可复现的运行时状态
3. 调用链或事件链
4. 输入数据、缓存、存储或配置
5. 副作用：请求、导航、写入、回调、订阅、资源释放
6. 最窄范围的临时观测点

## 根因与表象

示例：

- 表象：页面一直加载
- 根因：异步失败分支没有回写状态源，导致界面被动状态无法恢复

- 表象：列表项偶发显示旧数据
- 根因：条目身份不稳定，复用时绑定了过期状态

## 停止条件

出现以下情况时先不要编辑：

- 说不清触发路径
- 找不到责任层
- 指不出证据
- 无法判断修改会影响哪些旧路径
