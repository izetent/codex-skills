# 运行时日志

当本地证据不足，并且缺陷依赖真实运行环境、物理设备、浏览器、模拟器、容器或类生产环境时使用本文件。

## 通用流程

1. 明确要回答的问题。
2. 清理旧日志或缩小日志范围。
3. 执行最小复现路径。
4. 保存完整时间段日志。
5. 标记关键时间点、操作、请求编号、用户编号脱敏值或业务编号。

## Android 设备日志

### 常用流程

1. 通过 USB 连接设备。
2. 在设备上开启开发者选项和 USB 调试。
3. 确认设备可见：

```bash
adb devices
```

4. 实时查看日志：

```bash
adb logcat
```

### 常用变体

先找到进程编号，再按应用进程过滤：

```bash
adb shell pidof <your.package.name>
adb logcat --pid=<pid>
```

按标签过滤：

```bash
adb logcat <your.tag>:* chromium:* *:S
```

保存日志到文件：

```bash
adb logcat > android-device.log
```

复现前清理旧日志：

```bash
adb logcat -c
adb logcat
```

### 需要捕获的内容

- 崩溃堆栈
- 失败前后的警告和错误
- 事件、命令、回调或请求顺序
- 视觉问题相关的布局测量
- 网络、缓存、播放、权限、生命周期或资源状态变化

## iOS 设备日志

### 方式一：Xcode 设备与模拟器窗口

1. 通过 USB 连接 iPhone。
2. 打开 Xcode。
3. 打开 `Window > Devices and Simulators`。
4. 选择设备。
5. 打开设备控制台，或在复现时查看日志。

### 方式二：macOS 控制台应用

1. 连接 iPhone。
2. 打开 macOS 控制台应用。
3. 在侧边栏选择已连接设备。
4. 按应用进程、包名或自定义日志前缀过滤。

### 方式三：命令行设备日志

如果环境包含设备工具，使用团队可用的命令行工具读取已连接 iPhone 的日志。具体工具以项目环境为准。

## 运行环境中应记录什么

- 应用生命周期事件
- 命令、事件、回调时序
- 视图框架、视口、布局数值
- 播放、媒体、网络、缓存、权限状态变化
- 请求、响应、会话、业务标识

## 规则

以下情况最适合做运行环境专项排查：

- 缺陷只在特定设备、浏览器、系统版本、容器或线上环境复现
- 性能、时序或资源释放与本地环境不同
- 相机、音频、播放、图形处理器、网页容器、硬件加速渲染、后台任务或系统权限参与其中
